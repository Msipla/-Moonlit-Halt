# Numen × DeepSeek 真实自主建造｜下一阶段 Work 任务书

**状态：** 2026-11-20 已执行。各项实测、未验收条件及复现步骤见 [真实模型实验记录](live-lab/README.md)。
**仓库：** `Msipla/-Moonlit-Halt`
**研究基线：** `codex/numen-create-research` 的 `research/technical/numen-create-vs2/`，研究提交 `d19cec9`。
**目标环境：** Minecraft 1.20.1 / Fabric / Numen 0.1.5-beta / Create Fabric 6.0.8.1；具体锁定依赖以 `dependencies.tsv` 和现有复现记录为准。

## 开始前

1. **必须先读取最新** `Msipla/Conversation-Archives/AGENTS.md` 和目标仓库 `AGENTS.md`（如存在），整个任务遵守适用协作规范；若不可读取，明确报告，不得假装已遵守。
2. 读取本任务书、同目录 `README.md`、`SOURCE-MAP.md`、`REPRODUCE.md`、原始证据、脚本和探针，并核查 `projects/minecraft-mods/experiments/ai-engineer/TASK.md` 与 `mobile-base/TASK.md` 的最新状态。检查分支和并发修改。
3. **先复用现有实验**，不重新调查 Numen 基础架构，不重写已经可用的夹具、Lua、Skill、探针，不修改 Numen 上游。先验证本轮真正需要的依赖、可用性和证据。

## 核心目标

检验真正的 DeepSeek 模型是否能通过 Numen 的原生工具、Lua 和 Skill，根据玩家的**中文自然语言目标自主规划、施工、观察、纠错并验收**。上一阶段只验证了预写脚本驱动的动作链，不能把它的 46/46 方块和断轴修复成绩当成大模型自主成功率。

### 1. 安全接入和最小握手

- 优先使用 DeepSeek 官方 Chat Completions：`https://api.deepseek.com`；先试 `deepseek-flash`。按当前官方文档核对模型 ID、工具调用、思考模式与 Numen 兼容性；必要时在同一模型上调整思考设置，不盲目引入多供应商适配层。
- **API Key 只能从执行环境的安全秘密配置或运行时环境变量 `DEEPSEEK_API_KEY` 读取。** 不得从聊天内容、GitHub、报告、历史日志中提取密钥，不得硬编码、打印、提交、回显或写入成果包。用户曾在聊天中直接提供过密钥，视为已暴露；执行时要求用户在安全渠道配置**新生成的密钥**，不复用聊天中出现的值。
- 若执行环境不能安全接收凭据，不得假称已完成真实模型测试；先做不依赖密钥的准备，并准确报告阻塞。不得用固定 Lua 脚本替代模型来冒充成功。
- 先做一次真实 API 连通性及工具调用握手，再验证模型能自主调用 Numen 扫描一个指定方块并返回实际 ID/坐标。记录模型 ID、成功与否、匿名化回执和 token 消耗。

### 2. Create 自主工程对照实验（本轮首要验收）

在**全新隔离创造世界**内，以同等材料、空间和中文任务要求依次测试：
- **A：原生 Numen**，无专用 Create Skill / 状态插件；
- **B：原生 Numen + 已归档 Create Skill**；
- **C：原生 Numen + Create Skill + 现有 `createlab.machine.inspect` 只读探针。

玩家只提出目标：「用水车建一台 Create 粉碎机，用碎石试车；机器有故障时检查并修复，最后说明故障和产物。」不向模型发送上次实验的固定方块清单、精确坐标、预写 Lua 或标准答案。可向模型提供正常的模组知识、Skill、游戏内感知及施工范围。允许模型自己写 Lua、读配方、规划和迭代；夹具只负责环境、材料、统一投料、注入故障和**独立验收**。

验收包括：机器真正运行、粉碎轮两侧有符号 RPM、应力与容量、控制器有效性、实际产物；首次成功后管理员注入错误轴向故障，只告诉模型「机器停了」，观察它能否自主定位、最小修复、再次产出。记录每次真实模型工具调用、Lua、错误和回滚、额外搭/挖方块、用时、token/费用；区分独立测量与模型自述。A/B/C 失败也要如实保留，不用预写修复脚本补齐自主成功率。必要时有限次重试，说明重试次数。

### 3. 中文建筑与移动基地配合验证

在 Create 测试之后，单独让真实模型根据自然语言建造**可供现有移动基地 Mod 手动装配的静态船壳、内部通道、基础内饰及机械安装位**。不调用、不修改移动基地装配器，不要求 Numen 自动组装或驾驶。允许用户指定尺寸、风格、用途，但不能以预制固定蓝图冒充自由规划。核验内部可通行性、建造完整度、方块朝向、障碍和脚手架残留、设计区外修改、施工耗时。若无图形客户端，不声称已完成视觉美学或玩家实机验收；提供可供玩家下载或复现的存档、坐标和使用说明。

### 4. 实施边界与必要修复

- 复用已归档的 `mc20`、`fabric-probe`、`lua`、Skill、证据与测试脚本；允许在独立实验分支做最小必要改动，使真实模型对话驱动现有工具，并在明确需要时修复探针或 Skill。
- 不另造 AI 建筑引擎，不改 Numen 核心，不重构旧 AI 工程助手，不修改稳定版移动基地 Mod，不碰其他 Minecraft 项目、Pages 或真实玩家存档。
- 优先处理实际发现的阻塞；在不破坏已验证行为前提下自主修复、编译、复测。重大架构改变、跨项目改动或新权限需求先询问。
- 只使用隔离测试世界和受限施工区域；不要让模型的建造/挖掘动作影响其他项目。检查 Numen 的额外寻路方块、直接写入与玩家操作比例及权限模式。
- 复杂多关节变形、航空学飞行、VS2 自动驾驶本轮不作为硬性目标，不为它们增加新的框架。若核心实验进展顺利，可做小规模探索并清楚标为扩展验证。

## 交付与验收

1. 提供实际使用的模型、端点（不含密钥）、配置方式、环境、运行命令、必要最小代码/Skill 变更、可重现的独立世界与测试步骤。
2. 分别报告 A/B/C 的成功/失败、工具调用链、真实世界状态、故障恢复、额外改动、耗时、token 与费用。记录日志须脱敏；不得保存 API Key 或 Authorization 头。
3. 给出中文船壳建造的实际世界成果、可复现入口和明确限制；有图形实测才附真实截图/录像，没有就说明。
4. 在隔离开发分支提交必要源码与精简证据，检查并发变更、回读验证，报告提交 SHA；不直接合并 `main`。大型原始日志/世界文件若不适合 GitHub，可提供下载包并在报告中说明保存位置，不塞进源码仓库。
5. 根据真实结果提出**最小下一步**：继续使用 Numen、补一个具体接口、改进 Skill，或暂缓替换旧 AI 工程助手。明确区分已实现、已编译、真实 API 调用、真实游戏运行和玩家验收。不得将本阶段实验结论写成已部署稳定版。
