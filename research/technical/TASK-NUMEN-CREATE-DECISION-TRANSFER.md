## 核心问题与实验假设

上阶段开口版在同一模型、存档、委托和 420 秒限制下连续两次完整闭环：264.874 秒、229.931 秒；模型自主投料、读到新产物、清理、回复，独立磨粉与建筑保留通过。但仍有回扫。不同目标“原位磨石改相邻小齿轮侧驱”中，模型已获得观察结果，却反复逐层勘察，五次触及 200 API 调用上限，随后长篇规划生成 4096 token、`finish=length`，没有施工。侧驱物理可行性尚未实机证明。

假设：关键瓶颈是模型在“已有足够信息 → 形成少量候选 → 用现有 `build.diff` 核对 → 执行”之间未及时切换，而非缺少更大的扫描模块。先通过现有夹具的**小规模可观测对照**检验假设；不得预先将假设写成结论。

## 实施边界

1. 先只读分析侧驱失败轮的关键轨迹，分清机械知识或几何不可行、工具返回误读、候选迟滞、长篇文本生成等不同原因。必要时用无模型的真实游戏最小测试检查侧驱机制是否可行；若 Create 实际不支持所设侧驱结构，应修正测试目标/判据并说明原因，不把不可能任务归咎模型。
2. 复用现有隔离存档、房主模块、原始任务与夹具。在夹具或现有 Skill 中以最小、可撤销的方式对照一个**决策转换节点**：收到足够机械和开口信息后，模型应自行给出少量候选格及其依据，或者指出唯一一项确实影响施工的缺失信息；候选由模型生成，再使用既有 `build.diff` 检查并进入施工。不得写死坐标、直接给施工方案、由 Work 代为规划、自动替模型调用建造 API，或引入新的通用状态机。
3. 允许针对长篇规划导致 `finish=length` 的问题做最小实验性限制，但应保留模型真实决策空间，并记录是否只是把失败推迟。尽量把对照放在夹具中，不要未经验证污染稳定版 Skill。
4. 优先以此前失败的侧驱目标验证迁移；若物理先决条件未通过或任务定义本身不合理，则选择一个不同于磨坊搬迁、可独立验收的较小 Create 目标，并说明切换依据。对照必须保证相同起点、模型、权限和任务文本；420 秒为**每次模型轮次**上限，不是 Work 总时长。
5. 独立记录首次有效候选时间、首次 diff、首次真实施工时间、重复扫描、Lua 调用下界、请求、token、完成回执、实际机械传动/产物、建筑差异与截止隔离。严格区分模型自验、夹具独立验收和未施工。无模型验证不能冒充自主迁移。
6. 仅进行足以区分假设的少量实验；若出现同类重复失败且无新证据，停止并报告结构性阻塞与最小后续方向。无需每个小修复请示，但重大架构、权限、目标变更须确认。
