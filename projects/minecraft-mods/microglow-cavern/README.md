# 微光巨洞 · Minecraft 自然景观技术原型 0.1

状态：**实验设计 / 尚未实现**。本项目是独立技术验证，不是可安装 MOD，不与《月下小站》WebGL 工程混用。

## 目标

在 Minecraft Java 1.20.1 中，验证玩家从**安全的观察平台**望向一座**巨大、低照度、局部微光的地下洞穴**时，是否能够获得稳定且有层次的空间体验。风格强调神秘、尺度与探索欲，而非惊吓、追逐或密集怪物。

## 核心假设

1. 固定测试场景可以先分离「构图和光照」与「世界生成」问题。
2. Minecraft 原生方块光照、天空光照和可选客户端渲染方案能力不同，必须实测而不是凭独立 WebGL 效果推断。
3. 巨洞可见距离、遮挡、渲染距离、LOD/远景方案与性能互相制约，需要在真实游戏环境测量。

## 实验顺序

### A. 固定场景验证（第一优先）
- 在测试世界中制作一个可复现的巨洞、远处轮廓、少量发光体与安全观察平台。
- 不必先写自定义世界生成器；允许使用现成编辑工具/数据包/结构或最小 MOD，只要记录制作方式并可复现。
- 记录无着色器和可选着色器的差异；避免把第三方效果当作 MOD 原生能力。
- 记录截图、游戏版本、加载器、渲染距离、光源位置、设备与实际性能。

### B. 光照能力边界
- 区分方块光照传播、发光方块/实体的视觉表现、材质自发光、动态光源与后处理。
- 分别记录哪些效果无需改动渲染管线，哪些需要客户端兼容层或专用渲染实现。
- 不预设所有目标都能通过修改一个“光照逻辑”实现。

### C. 世界生成最小实验
- 只有固定场景通过美术与性能评估后，再选择一个可重复生成的大洞穴结构/地形特征。
- 检查生成稳定性、区块边界、存档兼容性及与现有世界生成组件的关系。

## 初步验收标准

- 能在明确记录的 Minecraft 1.20.1 环境中进入测试世界并到达安全观察点。
- 观察点能辨认至少三个景深层次：近景遮挡、中景洞穴主体、远景巨大轮廓。
- 低照度但路线与关键地形仍可辨识；光源不会把整个洞穴照成白天。
- 提供游戏内截图与运行证据，记录帧率和环境；任何尚未测得的数据标为未验证。
- 清楚标明哪些是手工布景，哪些由算法生成，哪些依赖着色器或其他 MOD。

## 不做的事

不增加怪物、战斗、任务、装备、完整生态或大型水下城市；不把单次手工布景冒充程序化生成；不预设 Fabric/Forge、DH 或任何特定渲染 MOD 必须采用，待技术调研和实测后选型。

## 与《月下小站》的关系

只复用**设计和验证方法**（目标描述、实景对比、用户反馈、迭代记录），不直接复用 WebGL 渲染代码。共享的美学观察可记录在 `research/aesthetics/`。
