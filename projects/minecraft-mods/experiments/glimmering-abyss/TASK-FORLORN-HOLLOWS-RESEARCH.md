## 2. 需要回答的技术问题

以**实际源码调用链和数据文件**为证据，逐项分析：

1. 异寂空谷的峡谷/洞穴轮廓、岩壁、岩台、空洞与高度分布由什么机制生成？区分地形雕刻、特征、技术结构、模板与后处理。
2. Underzealot Borough 如何确定生成条件、位置、朝向、高度和结构规模？究竟是**先选择自然地形安置聚落**，还是**先确定结构再适配/改造地形**，或二者结合？找不到证据则标未知。
3. 建筑、桥梁、道路、支撑和岩台怎样衔接？是否采用 Jigsaw、结构池、模板、地形采样或自定义处理器？分别列出已证实与未证实机制。
4. 随机种子、区块边界、跨区块放置、生成顺序、重复率、结构完整性、性能和与其他世界生成 MOD 的潜在兼容风险。
5. 对照本工程 Minecraft Java 1.20.1 / Fabric 的现有生成路径，辨析 Minecraft 共通机制、Forge 专用 API 与 Fabric 适配需求；不得假设 Forge 源码可直接编译到 Fabric。

**证据标准**：引用上游和本工程的具体文件路径、关键类/方法、行号或稳定 commit 链接；解释因果链。明确标注「源码证实」「推断」「未知」，不要把游戏外观、Wiki 描述或理论可能性写成源码事实。

- 对应的上游证据和本工程现状；
- 最小可行实现思路（只设计，不编码）、Forge/Fabric 差异；
- 对冷蓝环境、局部暖光、维多利亚建筑、宁静安全与已验证成果的影响；
- 对新旧世界、性能、区块生成及兼容性的风险；
- 可重复的验证方法及是否需要玩家美学确认。

保持「先有深渊，后有文明」的既定方向；只借鉴生成思想，不引入上游恐怖氛围、敌对生物或整套依赖。尊重上游许可证和署名义务，不未经核实复制代码。
