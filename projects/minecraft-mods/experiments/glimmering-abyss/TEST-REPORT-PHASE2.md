## 审美依据与范围

重新读取仓库 `research/aesthetics/glimmering-abyss-vision-2026-10-12.md` 和 `glimmering-abyss-conversation-excerpts-2026-10-12.md`，以天然深渊自身的微弱环境光、可辨认的远处空腔与巨构轮廓、独立的未来文明灯光层次为依据。

## 真正运行过的三套方案

| 方案 | 显示环境底光 RGB 系数 | 距离混合（格） | 远端 RGB／最大混合 | 原生微光源 |
| --- | --- | --- | --- | --- |
| A 原版基线 | 不改 lightmap | 实测 230.4–256.0，原版参数 | 原版状态 | 5 级；关闭额外光斑 |
| B 自然空间 | 0.36／0.40／0.44 | 24–224 | 0.006／0.009／0.013，0.92 | 5 级，小表面光斑 |
| C 巨构远景 | 与 B 相同 | 36–360 | 0.012／0.018／0.026，0.64 | 与 B 相同 |

世界依然无天空光、`ambient_light=0.0`；B/C 提供的是客户端 **显示可见度**，并没有虚构新的世界光级。方块光越强，底光补偿越弱；15 级强光保持原版值。各通道使用 `v + (255-v) × floor × (1-blockLight/15)`。

距离层次借用原版 terrain shader 的 `smoothstep` 与 fogColor.a，混合到很暗的蓝灰黑色。C 限制最大混合量，保留至少 36% 输入色；这不是对未加载区块的可见性保证。未使用可见雾粒子、全屏滤镜、后期泛光或第三方 shader。局部光斑仅在已有光源的暴露面上约 0.28 格宽，系数 0.48，经过深度测试，不增加原生光传播。

## 同机位与世界条件

最终 12 张主对照在同一客户端进程、同一服务端世界中拍摄；每套均为原生 5 级微光。按照片元数据核对位置、方向、画质、时间、视距全部一致。

| 机位 | XYZ | Yaw／Pitch | 用途 |
| --- | --- | --- | --- |
| tunnel | 0.5／39／90.5 | 180／0 | 安全近景与通道出口 |
| platform | 0.5／39／73.5 | 180／12 | 平台＋中景岩柱＋远壁 |
| edge | 20.5／39／66.5 | 165／15 | 护栏与深渊边缘 |
| overlook | 0.5／55／60.5 | 180／28 | 创造模式固定飞行俯视；洞底与巨柱 |

共同条件：1280 × 720、FOV 75、Gamma 0.5、Fancy、AO 开、16 区块视距／6 区块模拟距离、VSync 关闭、60 FPS 上限、HUD 隐藏、固定时间 18000。

第一阶段和第一轮中间方案为 12 区块。实际检查发现远壁处于加载边界，最终将 **三套方案同时** 提高到 16 区块以完成同条件比较，没有扩大地形。原三个落地机位不变；额外俯视点调整后已实测保持 Y=55。旧临时存档已丢失，不能宣称复用了那个存档；用相同生成器和种子重建，178,080 格采样指纹与第一阶段一致，并用第二个全新世界复核：

## 视觉检查与保留的失败案例

A 的近景路面、护栏和远壁明显偏暗，确认第一阶段反馈。B 能清楚读取近景，并在远处形成更强的暗部衰减；部分远壁和空腔因而重新隐没。C 的近景底光与 B 相同，在实际平台、边缘及俯视图中保留更连续的远壁和巨柱层次。

**开发侧暂建议 C 作为下一轮起点**，重点比较平台及俯视的 B/C 原图。C 的远景材质细节仍较多，进一步控制远景的细节／对比度可能有价值；不能据此宣布它已达到最终美学。

Veil 方案同样真正运行：更高底光、8–112 格混合到浅蓝灰，画面出现明显雾幕，大量远景材质被覆盖，不符合目标，保留为反例。

第一轮旧参数 B 24–320／0.90 与 C 差异偏弱，旧俯视机位主要显示平台地板。代表性实际失败帧和全部当轮参数、性能、运行记录保留在 `attempts/soft-distance/`，对应源码 `cda4c24`。没有删除第一阶段记录。

## 性能与渲染异常边界

实际渲染器：`llvmpipe (LLVM 20.1.2, 256 bits)`／`4.5 (Core Profile) Mesa 25.2.8-0ubuntu0.24.04.2`，CPU 软件 OpenGL。每机位等待 8 秒后采集约 5 秒完整帧间隔；以下是四个主比较机位的范围，不是长时基准。

| 方案 | FPS 范围 | P95 帧间隔范围 ms | 最大帧间隔 ms | 超过 100 ms 帧数 |
| --- | --- | --- | --- | --- |
| A | 17.22–18.00 | 65.74–68.76 | 86.46 | 0 |
| B | 17.08–19.12 | 62.04–68.67 | 89.27 | 0 |
| C | 17.09–18.93 | 63.48–69.15 | 109.43 | 1 |

完整每机位 FPS、median、P95、max 和采样帧数见 [performance.csv](evidence/phase2/performance.csv)。三组范围有重叠，短时单轮样本不足以确认独立 GPU 的性能成本。不能据此宣称目标设备稳定 60 FPS。

捕获元数据记录区块队列状态；主截图时 pending chunk/rebuild 已为 0。没有看到渲染方案阻止本次区块加载完成，但尚未做长距离连续区块加载基准。实际画面未见天空状态泄漏或大面积闪烁，主世界返回对照正常。护栏的 cutout 材质已出现在测试帧中；透明玻璃、水体、特殊粒子和第三方 shader 未验证。

## 环境排错与复现

源码已按节点保存至 GitHub：恢复源码 `cda4c24`、初次构建证据 `b3f0954`、实际帧驱动的参数与采集修正 `1bceff1`。研究、失败和路线调整详见开发日志。

云端只使用私有工具缓存：Gradle 8.1.1 的 Binary store／EOF 问题改用 8.2.1；AF_UNIX 检测按已有宿主 helper 适配；隔离 PID 导致的已完成 Loom 锁只在没有并行构建时清除。Fabric 安装器 Java 下载超时，改用相同官方依赖的 Python SHA-1/ZIP 校验，再调用未改动官方安装器自身的 launch-JAR writer。依赖记录与实际宿主脚本归档在 `host/`，第三方运行时包不提交。

一次完整采集后的 stdout 完成消息未落入日志，旧编排器拒绝通过；保留失败日志和真实 walk JSON，改为必须核对本次启动后新生成的完整清单、每张图片与最终实际按键碰撞记录，并重新跑完整流程。最终证据在 `client-completion-check.json`；没有补写游戏日志消息。

本地离线回环测试的 Mojang public-key 获取失败、缺少音频资源和原版 shader sampler 警告记录在日志中；游戏仍完成实际测试。云端仅准备官方字体与 Minecraft JAR 内置图形资源，跳过额外批量资产下载；环境音频未验证。普通桌面使用完整资产下载，不需要照抄云端代理、GLFW 或 Xvfb 参数。

```sh
./gradlew build stageTestMods
python tools/run_experiment.py --accept-eula --capture --phase2 --output evidence/local-phase2-run
```

需要 Java 17、Python 3、联网依赖与可用桌面显示。首次复现按 README 安装。生成的依赖、世界和缓存位于忽略的 `.runtime/`，服务端只监听 localhost。
