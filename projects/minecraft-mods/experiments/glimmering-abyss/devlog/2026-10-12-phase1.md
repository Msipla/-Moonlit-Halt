## 目标与实现选择

第一阶段优先取得可安装／可构建、可复现的 Minecraft 1.20.1 地形和光照实验。选择 Fabric 的独立维度与自定义 `ChunkGenerator`，便于隔离试验、固定研究种子、读取实际光照，并保持主世界生成不受本实验影响。

最终固定：Java 17、Gradle 8.1.1、Loom 1.2.8、Fabric Loader 0.14.25、Fabric API 0.85.0+1.20.1。版本相容性通过实际发布 JAR 的清单／依赖以及构建、正式服务端启动确认。模型全部使用 Minecraft 方块；不建立资产库或增加玩法系统。

地形由区块生成函数直接产生：固定种子 74102002、解析洞厅边界、平滑噪声底部／顶面、七根起伏岩柱、断崖、短通道、宽观景台与两格高铁栏。灯光位置固定，共 26 处，包含一个封闭校准段。0／5／15 级模式只改变光源自身亮度，使用原版传播引擎。

## 关键排错与调整

| 问题与实际表现 | 判断与处理 | 对游戏的影响 |
| --- | --- | --- |
| 云端 Gradle 默认代理地址无法连通 | 使用当前运行环境提供的代理，只设置本次进程参数 | 无游戏逻辑改动，未写入全局 Java 设置 |
| Loom 检测 Unix 套接字时遇到 EPERM 并中止 | 私有构建缓存中的检测改为报告“不支持”；保留原 JAR 与官方校验、提供可选恢复脚本 | 仅构建主机适配，未修改 Minecraft 类 |
| 新版 Fabric API 的构建元数据不受旧 Loom 支持 | 实际检查发布清单，固定相容的 Loader／API 版本 | 依赖选型调整，构建与运行通过 |
| 首次 GLFW 初始化失败 | 将 X11 显示和客户端置于同一执行环境，通过 TCP；使用官方 LWJGL 3.3.6 的 GLFW 3.4 原生库 | 只适配云端窗口系统，原版游戏渲染与光照保持一致 |
| 平台后方入口旁存在未封闭边缘 | 补齐后栏，并连通铁栏角部；加入对应地形和实际块状态检查 | 完整保护正常行走路线 |
| 第二个世界启动复用 Fabric 重映射缓存发生文件冲突 | 第二个测试建立独立启动目录；只复制官方引导依赖与当前 MOD，不复制旧世界、`.fabric` 缓存 | 更明确地验证新世界生成，模板不被修改 |
| 无玩家时光照读取全为零，而玩家在场时通过 | 发现校准区块已卸载；仅测试模式强制加载两块校准区块 | 自动测量修复；普通游戏不启用测试驻留 |
| 官方依赖下载偶发超时 | 增加复用已成功安装官方引导目录的 `--server-template` 路径；仍生成全新世界与缓存 | 提高复现效率，不复用旧场景数据 |

测试脚本检查本次客户端日志的完成标记，避免旧截图／旧结果文件误判成功。诊断记录保留在 `evidence/diagnostics/`，最终原始证据链接在 TEST-REPORT.md。

## 已知限制与下一步

5 级源在无遮挡直线上到第 5 格已降为 0，难以表现百米洞厅的远景；15 级只能改善局部。截图很暗，是原版基线结果，没有后期提亮。下一轮只优先研究低成本的远景可辨识层次，保持同一地形与机位，并区分显示照明与方块光传播。

当前云端是 llvmpipe CPU 软件 OpenGL，短机位采样约 20 FPS；不能外推目标显卡或宣称稳定 60 FPS。首次进入出现约两秒的加载迟延。Windows／PCL2 正常客户端安装、目标硬件、长时间运行、其他 MOD／光影兼容和音频仍未实测。
