## 实现与配置

本次没有改变 Terrain 或 ChunkGenerator。实验维度、种子、洞厅、路线与岩柱保持原样。独立 terrain shader 只在实验维度、干燥视角、明确选择新模式时接管 solid/cutout/cutout-mipped 图层；不覆盖 `assets/minecraft` 的原版 shader 文件。A/B/C/Veil 保留作历史/机制对照。

环境辐照由**世界位置 + 表面法线 + 材质**决定：半球方向底光与一个平滑区域光场叠加，让迎光远壁和底部可辨、背光柱面较暗。另有受控空气透视，当前最大混合量 0.26，至少保留 74% 输入表面颜色；原生视距/状态效果边界是单独项。不是整屏 Gamma 或纯蓝色覆盖。

| 参数 | 冷蓝 blue | 铜金 copper |
| --- | --- | --- |
| 环境色 RGB | 0.24 / 0.63 / 0.95 | 0.90 / 0.63 / 0.30 |
| 基础强度 / 区域强度 | 0.34 / 1.65 | 相同 |
| 区域中心 / 半径 | (-20, 52, -80) / 105 格 | 相同 |
| 方向 | (-0.25, 0.6, -0.75) | 相同 |
| 空气色 RGB | 0.07 / 0.34 / 0.57 | 0.52 / 0.30 / 0.10 |
| 空气距离 / 最大混合 | 30–235 格 / 0.26 | 相同 |

参数从 `config/glimmeringabyss-visuals.json` 读取；首次由包内默认 JSON 创建。`/abyssrender blue`、`copper`、`a` 切换；`/abyssrender reload` 读取修改，非法配置保留上一份有效值并报错。机制控制 `blue-clear` 关闭空气项，`blue-no-field` 关闭位置辐照。**配置文件读取和两色调切换已实跑；手动编辑后 reload、非法文件的游戏内交互尚未专门实测。**

世界的方块光/天空光及其传播不变，原生 lightmap 表也不变。原生光色在顶点采样后插值；环境增强权重随方块光增加而减弱，15 级权重为零。两张 reference 原图用于实际强光对照；不能将全图相同作为验收，因为暗部环境本就不同。

## 实际看图后的比较

- A：近景和远景均偏暗；新系统在保持暗部的同时让远壁与洞底出现可辨环境照明。
- B：近景提亮明显，但远处空间衰减更强；新系统的区域辐照使远壁与前方暗柱形成不同的层次关系。
- C：比 B 保留更多轮廓，但近/远表面多为相近的冷灰可见度；新系统保留暗柱面，并让迎光远壁更亮、有位置差异。
- Veil：环境色有参考价值，但雾幕覆盖远景。当前空气项限制为 0.26，并由表面/区域照明承担主要可见度；关闭空气项后远壁依然可见，说明不是只靠雾幕。
- 第一次 Phase 3：技术通过但空间光仍偏弱。第二轮增强区域光，实际平台及俯视中远壁更可读；旧参数完整保留。
- 原版灯笼：四个临时校准灯显示独立的暖色局部照明，原图为 blue-lanterns；没有把它们称为文明建筑或“活世界”完成。

这些是开发侧原图观察，**不是用户美学通过声明**。空腔仍是 Minecraft 石质实验地形，巨柱和洞壁的方块纹理/细节仍显眼；没有参考图的城市、暖窗、生活痕迹和巨大悬浮结构。近景局部灯光布局尚需设计。空间光场可能显得人工，最终效果需用户判断。

固定矩形采样见 pixel-region-measurements.json，仅辅助说明不同区域亮度，不是美学评分，也没有输出修改后的图片。原图对照比数字更重要。

## 性能

llvmpipe (LLVM 20.1.2, 256 bits) / 4.5 (Core Profile) Mesa 25.2.8-0ubuntu0.24.04.4。每个机位等待至少 8 秒，再记录实际帧间隔；若区块队列未清空会继续等待。统计来自短时单轮，同一机器的原版 A 平台为 14.83 FPS，不足以定量确认新 shader 的长期成本。旧 Phase 2 来自不同执行环境，不直接比较硬件成本。

| 方案 | FPS 范围 | P95 ms | 最大帧 ms | 超过 100 ms 帧数 |
| --- | --- | --- | --- | --- |
| blue | 11.38–12.97 | 83.17–120.55 | 167.29 | 30 |
| copper | 12.68–13.27 | 78.54–84.32 | 95.14 | 0 |

这不是目标 GPU 测试。完整 CSV 和逐帧 JSON保留，包括异常帧，不能宣称稳定 60 FPS。

## 环境与失败记录

本地沙箱 Java 的 Maven 请求超时，私有 Python Maven 中转配置仍很慢，已主动停止。诊断在 evidence/phase3/failures/java-maven-timeout.log。改用独立 GitHub 托管 Ubuntu、官方 JDK 17、Xvfb 和完整官方资产下载，未修改用户系统，未将依赖二进制提交工程。两次真实采集都独立保存；音频设备/听感仍未验证。

## 待验证与下一步

1. 用户查看原图，决定光照层次是否朝正确方向发展；不得再次要求从旧 B/C 中选最终方案。
2. Windows/PCL2 正式安装、目标 GPU 帧率、长时漫游和内存表现。
3. Sodium/Iris/Distant Horizons、透明水/玻璃、实体/粒子、第三方资源包的管线一致性。当前方法可能被其他渲染器绕过，不能标记兼容通过。
4. 区域辐照不做光线遮挡；厚墙泄漏、任意自然洞穴的光场选择、区域过渡仍未解决。本轮只验证预设有限洞厅，不等于可直接接入所有地下地形。
5. 原版局部灯光布局与宁静生活感是后续视觉设计；本轮不扩展城市、NPC、交通、生态或 GI 架构。
