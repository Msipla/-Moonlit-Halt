# 《微光深渊》v1.0 正式化开发任务书

**工程仓库：** `Msipla/-Moonlit-Halt`  
**工程目录：** `projects/minecraft-mods/experiments/glimmering-abyss/`  
**长期设计与管理档案：** `Msipla/Conversation-Archives`  
**开发基线：** Phase 7.5 / v0.7.5  
**目标：** v1.0.0 正式版（Minecraft Java 1.20.1 / Fabric，兼顾安卓 Amethyst 实机体验）

## 一、任务定位

将已完成技术验证的《微光深渊》原型发展为真正的地下深渊作品。早期为方便实验而设定的洞厅范围、房屋数量和景观尺度**不是最终设计上限**。

当前主要工作是扩充规模、重组空间结构、修正实际体验，而非重新发明已有机制。此前的技术验证有效，但**v0.7.5 的整体空间美学尚未通过用户验收**：当前更像人工开凿的封闭地下大厅和七栋小房子，而非存在文明痕迹的巨大深渊。

**长期设计原则：先有深渊，后有文明；文明依附深渊而存在，却从未真正征服深渊。**

v1.0 聚焦**一片有深度、有未知边界、可探索的自然深渊，以及其中一处温暖、空寂、无人却有生活痕迹的文明聚落**。沉沦海、被遗忘的硫磺海及其他独立地下区域留待后续版本，不列入本次交付。

## 二、开始开发前的恢复要求

先核对 main 最新源码、`HANDOFF.md`、`TASK-PHASE7.5.md`、`TEST-REPORT-PHASE7.5.md`、开发日志、发布包与测试证据、相关 Issues，以及 Conversation-Archives 中的原始美学与最新设计决定。以最新工程和用户实机反馈为准，不因旧档案的过期状态重复开发或覆盖成果。

保留已经有效的冷蓝环境、局部暖光、建筑风格、桥梁、缆车基础、梦境基础、生成保护和测试设施。仅在达到 v1.0 体验所必需时改动架构。

## 三、核心目标

### 1. 找回真正的“深渊”

现有空间太容易被看作边界清楚、岩壁圆润且规整的地下洞厅。需要建立更自然、巨大、层次丰富的深渊环境：

- 洞穴整体轮廓具有不对称的地质结构，不是单一圆厅、椭圆厅或规则穹顶；避免均匀岩柱、整齐平台和单尺度噪声。
- 存在明显的垂直落差、天然岩台、岩棚、裂隙、侧洞、远景与遮挡；深渊整体远大于聚落。
- 玩家不能站在一个位置便看清整个空间边界；远处与深处保留未知感。
- 至少提供具有实际探索意义的外围路径和返回路线，不只在墙面添加装饰洞口。
- 不要求每个地方都是悬崖，保留自然形成的平缓居住区域。

**不要只把原洞厅等比例放大、堆随机凹凸或复制岩柱。** 优先解决空间形成逻辑与自然感。允许评估更适合大尺度生成的技术方案，但仅在必要且有证据时调整现有实现。

### 2. 将七栋房屋原型扩充为可信的无人聚落

保留原有暖光、房屋、图书馆、铁索桥和安静气质，合理扩大聚落的生活尺度。房屋数量由体验与性能决定，不设机械指标。

- 形成自然的街巷、住宅、公共空间、作坊或生活痕迹，避免整齐陈列的景点感。
- 依附天然岩台，具有**轻微而舒适**的高低错落：短台阶、缓坡、桥梁；不要全部处于同一 Y 高度，也不要建成极端的悬崖城市。
- 建筑与地形相互嵌合，保留局部自然遮挡；图书馆与主镇的高差、桥梁及空间关系应有意义。
- 文明设施可完好、亮灯、可使用，但**暂时看不见居民**。不擅自加入 NPC，不擅自宣布居民死亡或将世界改成末日废墟。

小镇是安全庇护所和探索起点，而非地下世界的全部内容。玩家从外围望向小镇时，应能感受到黑暗深渊中的温暖归途。

### 3. 修正缆车轨迹与乘坐体验

安卓实机反馈：缆车**始终向下**，但下降途中突然向图书馆方向斜向偏移，又斜回原有地下站台，形成明显折线形横向运动；不是向上折返。

修正为连贯、平滑、有观景意义的下降线路，检查曲率、速度、车厢朝向、岩体/建筑/桥梁净空和起终点。保持真实可用的往返、提前下车和重连保护；重点检查安卓乘坐时的抖动、异常显示和突兀运动。

### 4. 修正梦境演出

安卓实机反馈：目前梦境在起床瞬间突兀弹出一张静态图，底部伴随意义不明的台词，破坏沉浸感。

让梦境与睡眠过程自然衔接，使用适度的淡入、停留、淡出或其他稳定的简洁演出；取消莫名固定台词，保持神秘、克制。不要求本阶段实现可交互梦境维度或复杂剧情系统。

### 5. 为未来区域留最小必要扩展能力

沉沦海、被遗忘的硫磺海以后作为其他地下区域开发。当前只在合理的空间连接、数据边界或最小必要接口上预留扩展可能。

**不要提前开发这两个区域，不要为了尚未确定的功能建立大型抽象框架。**

## 四、工程约束

1. **旧存档与玩家改动优先。** 不覆盖已生成的 Phase 7 / 7.5 景观；如新地貌仅适用于新世界，必须明确说明和测试。
2. 维持 Minecraft Java 1.20.1 / Fabric 正式客户端及专用服务端兼容性，兼顾安卓 Amethyst；不要把 Linux 自动化成功当成安卓实测成功。
3. 控制生成时长、区块负载、内存、渲染与玩家可达性；不为扩大规模牺牲稳定性。
4. 小镇及主要生活、观景、交通区域维持安全与宁静；不强行加入敌怪、战斗、追逐。
5. 保留正式构建、真实客户端/服务端证据、失败日志和历史交付，不伪造或覆盖失败结果。
6. 遵守三原则：**不把简单问题复杂化；不制造屎山架构；不为了改而改。**

## 五、开发组织

直接以 **v1.0.0 正式交付**为目标。允许 Work 自主划分内部里程碑和测试版本，不必机械凑 0.8、0.9 等版本号。

**先验证整体深渊空间与聚落关系，再大量精修建筑。** 如果需要对核心空间方案、已验证内容或生成架构作重大取舍，先提供简明依据和真实截图，请用户确认方向；其余工程选型、排错和执行路径自主决定。

不要让 1.0 无限膨胀：本阶段不做沉沦海、硫磺海、NPC 社会、完整生态、战斗系统或交互式梦境世界。

## 六、v1.0 验收标准

### 世界与美学
- 玩家能明显感到身处巨大、自然、不易一眼看清边界的地下深渊，而非人工大厅。
- 深渊有垂直尺度、远景、岩架和真实可探索的外围区域。
- 聚落规模、生活感与微地形明显改善；建筑与天然岩体自然融合。
- 暖光、安全、寂静、无人文明与未知深渊的反差成立。
- 玩家能够从小镇出发探索并辨识归路。

### 功能与稳定性
- 新世界正常生成，至少两个种子完成真实客户端与专用服务端验证。
- 缆车完整往返，运动平滑且没有明显折线式横向偏移、穿模或不合理折返。
- 梦境不再醒后突兀弹图配莫名台词，睡眠及正常游戏流程可靠。
- 房屋、道路、站台、桥梁与主要探索路线可用。
- Phase 7 / 7.5 已生成存档与玩家改动得到保护。
- 安卓 Amethyst 实机检查地貌、缆车、梦境、可达性和性能；未实测的兼容性必须如实标注。

v1.0 要交付的不是一座更大的地下大厅，而是《微光深渊》原本承诺的世界。


## 八、2026-10-14 安卓实机反馈：V1.0 有条件美学验收与收尾修复

**状态：用户提供六张安卓 Amethyst 实机截图并明确提出问题；V1.0 尚未获得最终美学验收。** 本节是对前述 V1.0 目标的具体化，不推翻已认可的冷蓝光、少量暖窗、深渊落差、建筑时代风格及现有有效成果。工作开始时必须重新检查最新开发分支、PR、HANDOFF、生成源码与真实测试结果；本节不预判问题根因，也不声称已完成修复。

### A. 异常方块与悬浮残留（优先）
- 玩家在街道旁看见孤立的深青色方块，在深渊远景中亦疑有零星悬浮块。**截图无法确定具体方块 ID 或生成来源**；先通过实机定位/取样、世界生成代码及结构模板确认其身份与是否有意放置。
- 若为非预期残留，修正源头（模板、放置顺序、边界、生成后清理等），不要用额外装饰遮盖。保护有用途的标记/交互块，不能仅凭颜色全局删除幽匿类方块。
- 验收：主要街道、观景点、桥梁和深渊视线中不再出现无意义孤立块；提供修复前后同机位真实截图和必要的方块定位证据。

### B. 洞壁自然度（最高美学优先级）
- 用户指出洞壁像人工砌筑/开凿。实机图可见大量重复的纵向条纹、均匀台阶、连续等高曲面及过度规则的顶壁衔接；重点解决**地貌几何生成规律**，而非靠散布装饰方块伪装天然。
- 局部打破重复周期、截面规则和一致坡度，形成不对称侵蚀、天然岩架/断裂与层次变化；避免另一种单尺度随机噪声或密集尖刺。保留已有深渊尺度、强烈落差、可见远景、巨柱与必要的安全通行面。
- 优先局部修改新增或问题显著的岩壁，不推倒重建小镇，不大改已认可的环境光。验收须有与用户反馈相近角度的真实原图。

### C. 可进入建筑的室内完成度（明确验收缺口）
- 用户明确反馈：进入房间后几乎空无一物，地上仅有工作台与熔炉。**这是室内设计未完成，不是要求街面继续堆装饰。**
- 对主要可进入建筑按用途布置可信的生活/使用空间：住宅的床、桌椅、收纳、照明；工坊的操作台、材料和工具区；商店的柜台货架；图书馆/公共建筑的阅读与公共空间。根据实际建筑种类选择，不强行给每栋套同一模板。
- 建立可辨认的空间动线与基本功能分区，陈设有差异、有克制的生活痕迹，符合“居民刚刚离开、仍有灯火”的无人聚落；不加入 NPC、恐怖叙事或末日废墟。
- 优先使用原版方块和现有素材，不引入大型家具依赖；保证门、楼梯、床边和房间主要通道可正常通行。至少对有代表性的住宅、工坊、公共建筑进行玩家实走与室内截图验收；其余可进入建筑不能仍是工作台/熔炉式空壳。

### D. 探索路线与回程体验（玩法优先）
- 用户反馈：沿探索道路走了一圈又回到起点，过程缺乏有意义的发现。**环线本身不算错误**，但必须使探索具备明确方向、节点、可辨认的终点或景观收获，并让返回成为有意识的捷径/闭环，而非无提示地白走一圈。
- 先核对当前可走路线的实际拓扑、岔路、地标、可达性和视线，再以最小地形/路径改动补齐探索目标、路线提示与返回逻辑。可以利用既有深渊观景点、岩廊和聚落，不必扩建新区域或设计任务系统。
- 验收：玩家从小镇出发，沿路线能发现至少一个值得停留且有清晰空间意义的节点，理解为何走到这里、如何回到小镇；实走记录须覆盖去程、节点和返程。

### E. 验证、保护和交付
1. **先核实问题来源再改动**：以最新工作分支和 PR 为准，注意其他 Work 会话可能并发提交；提交前重新读取文件版本，避免覆盖正在进行的 V1.0 成果。
2. **保护旧存档与现有景观**：明确哪些修复仅对新生成世界生效；不静默重铺玩家旧档、覆盖玩家方块或破坏 Phase 7/7.5 已验证成果。
3. **先有限度收尾，再验收**：不扩大小镇数量、不新增独立区域、不重做整套光照、不堆装饰。若核心空间结构必须大改，先给真实截图与依据请用户确认。
4. **工程验证**：必要的生成回归、客户端/服务端运行、两种子检查、室内通行和探索实走；检查安卓 Amethyst 兼容与性能。无法亲自完成的实体安卓验证应明确交给用户，不能冒称已通过。
5. **交付**：修复说明、真实游戏原图（包括室内、洞壁、异常方块位置、探索节点）、构建 JAR/SHA-256、最新测试结果、HANDOFF 与必要的长期档案更新；不覆盖历史失败证据。

**最终验收判据**：玩家既能被巨大而自然的深渊震撼，也能走进有真实生活痕迹的空寂小镇；探索外围有发现、有归途，不再被突兀方块、人工规则洞壁或空房间破坏沉浸感。用户最终确认前，不宣布 V1.0 美学验收通过或正式发布完成。
