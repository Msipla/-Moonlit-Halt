# Project 02 · 微光深渊（Glimmering Abyss）

**类型：** Minecraft Java 1.20.1 地形／光照技术可行性原型  
**状态：** 立项与验收设计；尚无 MOD 源码、游戏内截图或运行结果  
**原则：** 技术验证优先，美学目标驱动；与《月下小站》WebGL 工程独立。

## 要回答的问题

能否在 Minecraft 1.20.1 的真实游戏中，以可复现的世界生成或结构生成方式，提供一处规模宏大、可以安全观察的地下空间，并用有限光源形成微光、层次和可辨识的远景？在目标设备与合理渲染距离下表现如何？

## 最小体验

玩家沿短洞穴通道走向有护栏或天然屏障的安全观景台，看到宽阔地下空间、远方岩柱、断崖与少量微弱光源。重点是神秘、辽阔和安全地凝视危险；不以惊吓为目标。不增加怪物、剧情、战斗、任务或复杂玩法。

## 三条验证线

1. **地形：** 首先用可重复的固定种子／预设区域测试形体与可达性；随后验证真正的生成机制（世界生成、结构或其他合适方案），不可用手工建造截图冒充程序化生成。
2. **光照：** 先记录原版天空光／方块光和可见性边界；必要时对比着色器或自定义渲染。必须说明每个效果依赖的 MOD、光影或渲染器，不能把视觉后处理误称为改变光照传播逻辑。
3. **性能：** 记录游戏版本、加载器、MOD 列表、硬件、视距、光影状态、帧率与明显卡顿。不同配置的数字不能直接横比。

## 第一阶段交付与验收

- 一个可构建／可安装、能在 Minecraft 1.20.1 中启动的最小实验项目，或经验证更合适的最小可复现测试方案。
- 可重复进入同一测试场景；记录种子、坐标、版本、依赖与生成方式。
- 至少三个固定观察位置（通道、观景台、深渊边缘）的游戏内真实截图；如使用对比方案，保持机位一致。
- 说明哪些视觉目标已实现、哪些受原版照明／区块／可见距离限制，以及下一轮最值得解决的一个瓶颈。
- 附实际运行记录；**没有真实游戏内测试前不得标记完成**。

## 非目标

不制作完整地下生态群系、大型城市、剧情或正式整合包；不提前选择 Fabric／Forge、第三方渲染器或地形库。选型以兼容性、最小实现和实际验证结果决定。

## 与其他项目的关系

- `projects/moonlit-halt/`：已归档的独立 WebGL 美术实验，可复用设计与迭代流程，不直接复用其运行时。
- `research/aesthetics/`：整理微光、远景层次、阈限空间与安全观察危险的视觉原则。
- 本目录：Minecraft 1.20.1 内的实际生成、照明、性能与可重复测试证据。

## 下一步

在能运行 Minecraft Java 1.20.1 的电脑上，由开发执行者调研加载器／生成路径并搭建最小可运行项目；先拿到游戏内画面和测量，再决定是否扩展光照逻辑。
