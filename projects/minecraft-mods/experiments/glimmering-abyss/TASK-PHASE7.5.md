# 《微光深渊》Phase 7.5 任务书：从人工洞厅到天然洞穴中的庇护所

**实施更新：2026-10-13 v0.7.5工程技术交付完成，真实客户端/服务端运行38401293992全部通过。美学与安卓体验仍待用户验收。** 实际范围与取舍见[本阶段报告](TEST-REPORT-PHASE7.5.md)和[HANDOFF](HANDOFF.md)。

**任务书建立时快照（历史）：2026-10-13 用户确认开发方向；任务书建立，不代表已经启动代码开发或完成验收。**

## 一、恢复与原则

工程仓库 `Msipla/-Moonlit-Halt`，目录 `projects/minecraft-mods/experiments/glimmering-abyss/`。开发前读取 main 最新源码、`HANDOFF.md`、`TASK-PHASE7.md`、`TEST-REPORT-PHASE7.md`、安装说明、最新证据、Phase 6–7 实际截图及 `Msipla/Conversation-Archives` 中的最新审美决定。以**实际源码和最新实机反馈**为准，不把历史“待用户审阅”误当成尚未测试。并发工作时先核对最新 SHA/diff，避免覆盖其他会话成果。

坚持：**不把简单问题复杂化；不制造屎山架构；不为了改而改。** 保留 Phase 7 已交付的正常主世界生成、寻梦微光、入口、车厢往返、巨柱、冷蓝光、暖窗和局部禁怪；允许自主调研实现、调整开发顺序和选择简单可靠的替代方案。不要为了改美学而推倒整个洞厅或重写地形引擎。

## 二、唯一核心目标

把现在“人工开凿的巨大地下洞厅里摆着建筑”改为**“自然形成的庞大地下洞穴中，有人在适宜岩台上建造了一处温暖、安静、可居住的无人庇护所”**。

核心美学：宁静、神秘、宏伟、温暖、安全；**洞穴属于自然，建筑顺应地形**。玩家能从安全小镇欣赏巨大陌生深渊；神秘感来自亲身体验与环境细节，而不是克苏鲁/拉莱耶式的夸张文字承诺。整个景观依然禁止普通敌对生物及不期望的生物进入，不改变主世界其他区域的刷怪。**不新增 Boss、敌对怪物、NPC、强制任务链或庞大世界观解释。**

## 三、交付范围（按体验优先，不预设复杂架构）

### A. 地貌：先把洞厅变成洞穴（最高美学优先级）

保留已认可的中央巨型洞室、冷蓝氛围、巨柱、暖光小镇和主要观景构图。重点打破笔直墙面、等距感岩柱、平整底面、直上直下且像被截断的深渊。用**不对称岩壁、自然岩架、断层、局部斜坡、侧洞/窄通道、遮挡与纵深**塑造自然形成的洞穴系统；不要让它变成规则的盒子或人工竖井。地貌在小镇岩台附近可以被人修整，离开建筑应逐渐恢复自然。

**少量水**：可加入岩壁细瀑、渗水、局部静水池或小镇排水渠，服务岩层过渡与倒影；不要把中央洞厅变成整片地下海洋。保证流体受控、不扩散破坏结构、不形成异常更新负载。未来“沉沦海”式大型水域仅作远期候选，**不纳入本阶段**。

### B. 小镇：从模型变成可探索的庇护所

保留现有六栋建筑及有效美学，适度扩建到约 6–8 栋（仅设计目标，按地形和实测效果调整），使主要建筑可进入、有基础内饰、暖光和生活痕迹。可考虑住宅、书房/图书室、工坊、温室、观景房等不同用途；至少提供一处玩家愿意停留、休息的空间。无人但不荒废：灯亮、生活痕迹尚在，不靠长篇文案解释。避免外观好看但门打不开、内部空白或全是重复房屋。

### C. 桥梁：有明确目的地

现有桥梁不能仅是悬空装饰。使其跨越真实地形障碍，连接自然岩架、小镇或对岸明确可抵达的观景建筑/地点。玩家走到对岸应有新的景观、可进入空间或小型环境发现；不要求大型解谜和稀有装备奖励。优先保留已验证步行和护栏安全，别为加长而制造生成冲突。

### D. 梦境：以短暂视觉体验取代空泛文字

保留两晚睡眠逐渐引导和寻梦微光定位闭环。第一晚让玩家**看见**冷蓝巨型洞穴，第二晚让玩家**看见**无人暖光小镇；梦境结束后安全醒来，文字仅作克制、具体的简短记忆提示，避免暗示不存在的古神、巨大奖励或宏大剧情。

可评估复用现有实验维度，玩家睡觉时短暂进入安全固定观景点约 **6–8 秒**，随后自动返回床边；必须处理原维度/坐标、床、生命状态、断线/重登、区块加载及防坠落，不能遗留玩家在实验维度。**如跨维度实现成本或风险不合适，优先采用更简单的睡眠画面方案：各展示 1–2 秒的真实场景画面/贴图，随后正常醒来。** 不强求跨维度。不得将静态画面冒称为可交互维度。梦境必须适配安卓端。

### E. 实机问题修复与调试

- **乘车明显抖动**：排查服务端运动、客户端插值、乘客同步及 Android Amethyst 表现；以实际乘坐体验为验收。
- **缆车像电梯**：改善轨迹或视觉呈现，使玩家感觉在穿行、欣赏深渊，而非单纯垂直升降；可选择成本可控的设计，不预设复杂物理系统。
- **极少量疑似未渲染方块**：先区分生成缺块、区块加载与客户端渲染，再对症修复，不凭截图断言根因。
- **生成状态/提示**：明确区分选址/生成中、失败或等待、梦境进度、可定位等；不要一律提示“歇息片刻”。
- **创造模式验证指令**：仅创造模式可用，提供生成状态、梦境验证、安全定位已生成入口及缆车测试等能力；可能破坏世界的指令还需操作员权限。绝不能引导玩家提前传送占用候选生成区块。
- 对照 GitHub [#2](https://github.com/Msipla/-Moonlit-Halt/issues/2)、[#3](https://github.com/Msipla/-Moonlit-Halt/issues/3)、[#4](https://github.com/Msipla/-Moonlit-Halt/issues/4) 的已知问题和用户安卓截图；不要把记录问题等同于已经修复。

## 四、工程边界与安全

Minecraft Java 1.20.1 / Fabric，尽量保持普通世界兼容，不依赖整合包或全局重构世界生成。参考《海上机械师》与 Alex's Caves 的**地下空间组织与探索动机**，不移植它们的地形/资源/任务系统。

现有 Phase 7 已生成的存档及玩家建筑**不得被升级过程擅自重建或覆盖**。若自然化地貌需要新世界生成，明确新旧存档差异，保留旧景观与玩家改动；不要静默迁移。继续尊重未探索区块、地表覆盖、世界高度、基岩底界、每世界生成唯一性及持久化记录。维持地表唯一预期入口、完整景观局部禁怪、景观外正常刷怪、缆车安全返程及中断/重连保护。优先复用现有生成和测试体系，不另建大型框架。

## 五、实施建议与验收

开发顺序可自主调整，建议先验证**自然洞穴轮廓与小镇/桥梁的空间关系**，再补内饰和少量水景，随后处理缆车/梦境/状态提示，最后进行多个种子与安卓实机回归。不要为了堆建筑数量牺牲空间美学。

交付至少包含：
1. 正式可安装 JAR、源码、清晰版本标记、构建与安装说明；保留 Phase 1–7 历史证据和 Pages 链接。
2. 多个不同种子真实客户端/服务端生成测试，检查洞穴自然感、地表覆盖、区块接缝、水体安全、入口/桥/房屋可达、床/梦境/定位、缆车往返与重连；记录未验证项。
3. HARD 或其他非和平难度、`doMobSpawning=true` 的局部禁怪与景观外刷怪对照；不能因扩建漏保护。
4. 提供**真实 Minecraft 原始截图**（主洞穴整体、自然岩壁和底部、桥梁两端、小镇街道及室内、水景、梦境两晚）和简明前后对照；不要用概念图代替实机证据。
5. 由用户最终审美验收。技术测试通过不等于美学通过；如有未完成的目标，明确区分“已实现/待完成/不可行及替代方案”。

## 六、明确不做与后续方向

本阶段**不做**“沉沦海”式大型水域、新地下生态群系、完整 NPC/战斗/剧情、全面地形引擎重写、全世界地下替换或强制下界整合。未来可研究微光植被、独立地下水域、天然洞穴间旅行、第二目的地；这些只是候选，不提前锁死版本。

**最终体验判断**：玩家走入的是一片天然、巨大、陌生但安全的地下世界；小镇像在岩台上自然生长的庇护所；过桥有意义；梦境让人想亲眼找到这里；抵达后值得停留，且可可靠返回地表。
