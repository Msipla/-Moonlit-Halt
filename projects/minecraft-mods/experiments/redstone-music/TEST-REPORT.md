# Night Relay 原型验收记录

2026-11-19。工具链闭环、Fabric 1.20.1 部署与卸载后原版 1.20.1 回放均已验证。结论适用于此处的测试样本和原型边界，尚无 Windows 安装、其他歌曲或用户验收记录。

## 同一音频从 WAV 到工程

样本是原创 24 秒、100 BPM 的四声部测试曲。用 FluidSynth 与 TimGM6mb 将参考谱渲染成单个 WAV。工具链只读取混音，参考谱仅用于打分。参考音频与参考谱可用 `python tools/make_fixture.py fixture /path/to/TimGM6mb.sf2 --lead flute` 重建，需要 `pyfluidsynth` 及其系统运行库。用 `--lead guitar` 可重建第一轮吉他音色样本。

正式示例用 Demucs 分轨。YourMT3+ 从重组谐波声部识别钢琴和管乐，Basic Pitch 转录贝斯，ADTOF 转录鼓。管乐返回 GM 72 的模型类别，原谱用 GM 73 长笛，两者在这里按同一管乐家族计分。贝斯 GM 33 来自分轨角色分配。ADTOF 的力度固定，YourMT3+ 的力度也集中在同一数值。中间文件含力度和时值，不能据此反推原音配器的强弱。

每个参考音按音高、乐器家族和起音作一对一匹配，时间容差 110 ms。长笛和钢琴采用精确 MIDI 音高。鼓允许底鼓、军鼓和踩镲的对应 GM 别名。

| 声部 | 参考音 | 扒谱输出 | 正确匹配 |
|---|---:|---:|---:|
| 长笛主旋律 | 40 | 36 | 36 |
| 钢琴伴奏 | 60 | 79 | 54 |
| 贝斯 | 40 | 56 | 40 |
| 鼓 | 80 | 101 | 79 |
| 合计 | 220 | 272 | 209 |

保留了 18/20 个完整钢琴三和弦。该样本起音级召回率 95.0%，输出精确率 76.8%，共漏 11 音、多出 63 音。钢琴串音、贝斯重复和军鼓起音附近的额外踩镲是主要误差。生成时各旋律音保持原转录音高，钢琴轨里有几个超出竖琴音域的音符用了贝斯或长笛的原版音色。量化后整曲有 43 个同时发音的时点，单时点最高 9 音。

同一份输入转成 192 kbps MP3 后另跑完整转录，识别到 271 个音，其中匹配同样的 209 个，另误报了 3 个铜管音。该轮验证 MP3 解码与转录。部署包及游戏逐音结果采用 WAV 版。

第一轮吉他主奏样本保留了相同的参考音数。全分轨 Basic Pitch 的吉他匹配 12/40，直接采用 YourMT3+ 的清音吉他家族匹配 19/40，MR-MT3 输出只有钢琴和鼓两类。最终方案对两份样本的响应不同，吉他主奏保真度尚未达到可验收水准。工具链不把乐器编号当成配器识别正确的证据。

## 游戏内测试

在 Linux 上启动真正的 Java 1.20.1 图形客户端，使用 Fabric 0.17.2 和 Fabric API 0.92.6+1.20.1。单人创造世界中验证了潜行右键铁砧、选择配对文件、改名生成道具、空气右键信息、南/东两个朝向预览与放置。测试还验证了空资源包说明、有资源包元信息时的原版 HTTPS 链接确认框，以及有箱子时拒放。拒放后读取到箱内原有的 `{Slot:0b,id:"minecraft:diamond",Count:3b}`。占地 24×8×47，共 1,367 个方块，含三个独立按钮和纯文字告示牌。

| 同一存档改用未修改的 Java 1.20.1 服务端 | 计划 | 实际 Note Block 音效包 | 音高/音色错误 |
|---|---:|---:|---:|
| 南向，整曲 | 272 | 272 | 0 |
| 东向，整曲 | 272 | 272 | 0 |
| 南向，开头试听 | 54 | 54 | 0 |
| 南向，音色展示 | 6 | 6 | 0 |

测试玩家用原版右键交互触发木按钮。原版服务端未加载模组、数据包或资源包，命令方块设置为关闭。测试程序记录服务端真实发出的音效和位置，按音色、音高及旋转后坐标逐一核对。两方向计划首尾间隔 23,700 ms，实测为 23,699.96 和 23,700.12 ms。以收到的数据包墙钟时间计算，南向 95% 的起音偏差在 3.41 ms 内，东向 95% 在 8.90 ms 内，东向最大偏差 73.01 ms。墙钟偏差包含调度和网络抖动。

参考谱对照中，Redstone Music Generator 的适配结构在 1.20.1 发出同样的 220 个音，长度 478 格。Midicraft 的等价参考工程为 24×8×13，原版逐音核对也为 220/220。正式输出用紧凑布局和交错半 tick 路径，正式示例包含确实使用半 tick 的事件。

JAR 由 Java 17 和 Gradle 8.14.3 构建。部署包内 JAR 的 SHA-256 为 `2b12afc6471e43e77a13345513ddf1c366ebd57d72d5e4d1592cd2397948ee81`。部署包内模板 SHA-256 与逐音记录一致，模板重导出的解码方块、告示牌和编排数据与测试样本相同。导出阶段使用上游 Midicraft/Java 25 的 26.3 游戏库，旧版方块兼容性由模板白名单和实测共同核验。

尺寸、占地、区块、实体和方块冲突检查随 Mod 一并交付。现有实机证据覆盖了实例的南向、东向与已有容器拒放。北向和西向使用同一原版旋转接口，未重复做逐音实机验证。超上限的大型工程会拒绝，未做持续性能压力测试。

样本保留 1.20.1，26.3 仅用于外部规划。部分吉他布局依赖 26.3 的羊毛台阶，1.20.1 导出遇到该类未知方块会中止。额外资源包分支仅验证信息和链接确认。已核对 1.20.1 音符盒实现的可调音分支与玩家头颅自定义声音分支，后者不会随 `note` 自动变调。原型没有用头颅拼接自定义样本。[音符盒机制参考](https://minecraft.wiki/w/Note_Block)
