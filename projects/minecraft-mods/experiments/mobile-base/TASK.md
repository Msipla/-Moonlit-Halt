## 产品目标与不可妥协体验
玩家只会建筑也能造移动基地：用普通方块自由建造结构 → 放置载具核心 → 自动识别结构边界并高亮预览 → 选择陆地/船舶/飞行/潜艇类型 → 系统基于已安装成熟 Mod 的真实机制**规划、补齐并配置必要机械组件** → 用户确认 → 组装为真实物理载具 → 驾驶或巡航，在移动载具内部自由活动 → 停车、安全解除物理化、修改建筑、重新装配。

- **不接入 AI API、不做自然语言建造**；这是确定性规则和经验证的装配方案，不是另一个 AI Engineer。
- **不重写 VS2 物理引擎，不靠无形推力假装机械正常运行**；优先调用现有物理、轮组、传动、浮力与控制实现。确需少量适配须有源码证据。
- **不强制玩家学习 Create 机械结构**；系统尽量自动安装、连接、配置现有组件，尊重玩家已安装的可用组件，避免重复替换。
- 不限制预制蓝图或特定外形；允许异形建筑，但无法满足物理或装配条件时应明确告知而非伪称可行。
- 默认不破坏玩家原建筑；安装前预览、空间/碰撞/质量检查、明确确认；失败时保持原样或可靠回滚。
- 创造模式优先；生存模式应考虑材料/库存与不凭空生成，首版不必完整实现。
- 停车与解除物理化是两种不同操作。解除前检查静止、姿态/方块网格对齐、空间占用、方块实体与物品数据；不安全则拒绝转换，绝不静默丢失基地。
- 基础巡航与离开驾驶位后的移动居住体验重要；自动寻路/避障非首版要求。

## 分阶段执行（可自主实施，不需逐项请示）
**阶段 0：可行性门槛。** 核实上述现有 Mod 的实际源码和接口，确定最少依赖、加载器、许可证、版本及可行装配方式。尤其验证自动机械装配和安全解除组装是否已有可复用机制。若关键能力不可行，先提交明确证据和最小替代方案，不要为达成目标擅自重写底层或大量打补丁。

**阶段 1：最小纵向切片。** 选择源码证据支持、最快可测的一种载具（优先房车；若船舶明显更易则先船舶并说明理由），完成核心放置、连通范围识别（避免沿地面无限扩散）、预览确认、最少机械组件自动补齐、真实物理组装、驾驶与停车。不要一开始实现四种类型的空壳。

**阶段 2：移动基地闭环。** 验证玩家可在运行中的载具内部行走、使用至少一个容器/工作方块；尽可能完成基础巡航；安全解除组装、编辑并重新组装，验证方块实体/库存保留与失败保护。遇到现有 Mod 不支持的环节如实报告，不得用模拟测试冒充游戏实测。

**阶段 3：按证据扩展。** 在首种载具闭环可靠后，才研究第二种类型；飞机、潜艇、复杂机械自动规划、自动寻路与 AI 均非首版必需，不要为此提前造抽象框架。
