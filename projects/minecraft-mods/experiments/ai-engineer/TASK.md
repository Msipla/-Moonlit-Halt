# Minecraft AI 工程助手｜自主开发任务书

**状态：** 已授权的实验项目，尚未开发或验收  
**仓库：** `Msipla/-Moonlit-Halt`  
**目录：** `projects/minecraft-mods/experiments/ai-engineer/`  
**基线：** Minecraft Java 1.20.1 / Fabric；具体 Create、Valkyrien Skies 与附属模组版本以执行时核验的兼容组合为准。  
**执行者：** Codex Local / Worktree；以效率、真实运行成果和可验证性为优先。

## 执行前强制核验
1. 先读取 `Msipla/Conversation-Archives/AGENTS.md` 最新版及本仓库 `AGENTS.md`（如存在），整个任务遵守适用规范；无法读取时明确报告，不得假装遵守。
2. 检查本仓库最新分支、现有 `projects/minecraft-mods/` 结构、已有工程与并发修改。仅在本项目独立目录开发；不得修改《微光深渊》、月下小站、Pages 或其他既有成果。
3. 检查现成 AI 建筑项目的源码、许可证、兼容性及复用价值。限定短时间调查，能复用就复用，不合适就直接实现最小必要部分；不得复制不兼容许可证代码。

## 目标与执行策略
让玩家以中文自然语言下达工程指令，由 Mod 调用可配置的 AI API，规划、预览、确认、建造和验证 Minecraft 结构。优先支持创造模式；生存模式以后复用相同的工程方案和方块定义，不另造一套生成系统。

**第一优先级的端到端验收：** 玩家要求「建造一台使用水车驱动的 Create 粉碎机」，系统完成规划与实际放置；在真实游戏测试中验证水车动力、传动、应力/转速与粉碎轮处理物品的结果。不能把方块摆放成功、编译通过或模拟测试当作机器实际运行。

允许自主开发、安装必要依赖、编译、启动隔离测试世界、分析日志、修复错误、重复测试、提交代码，无需逐项请示。遇到阻碍应自主调整实现路线，优先形成可运行的纵向切片，不为凑齐全部功能而拖延核心交付。

## 功能范围
- 中文自然语言指令；API 适配尽量兼容常见 OpenAI 风格接口，可配置模型、端点和密钥；密钥仅使用本地安全配置或环境变量，绝不提交。
- 方案结构化输出与本地合法性校验：方块 ID、坐标、朝向、占用范围、构建数量限制；失败时提供清楚的原因。
- 创造模式：预览/确认、自动建造、撤销；仅允许在指定安全测试区域修改方块，保护玩家存档。
- Create：从简单可运行动力链开始，逐步实现粉碎、洗矿等实际产线；优先复用经测试的功能模块，允许 AI 自由规划外观与布局。
- Valkyrien Skies：在核心链路稳定后尝试载具装配与运动测试，必要时验证 Eureka/Clockwork 兼容性；不得仅凭外观认定成功。
- 生存模式：至少设计共用方案的数据路径；时间允许再实现材料清单、库存检查和分步施工。自动寻路/采集非第一轮必需。

## 测试与交付
1. 至少完成构建与隔离环境的真实 Minecraft 游戏内集成测试；优先自动化、GameTest、日志/状态断言，能获取时保留真实截图或录像。无法运行真实游戏时必须标为未验证，不能以静态检查替代。
2. 机械测试记录动力状态、转速/应力和至少一次实际物品处理结果；载具测试记录装配、移动及异常。
3. 提供可安装 JAR（若构建成功）、依赖与安装步骤、最小使用说明、测试命令、构建/运行日志、必要截图、SHA-256、已知限制、Git 提交 SHA。
4. 清楚区分已实现、已编译、自动测试通过、真实游戏运行通过、未验证和失败；不得虚构证据。
5. 开发完成时更新本任务书状态或最小必要交接内容，避免重复文档；保持提交可追溯，提交前检查并发变化，提交后回读核验。

## 安全边界与取舍
- 不修改已有正式 Mod、不使用用户真实存档做破坏性测试、不上传 API Key。
- 不进行无必要的大型架构重构；不要为了功能列表而造大量空模块。
- 如测试环境缺少客户端图形能力、外部 API 或物理模拟依赖，先完成可独立验证的部分，明确剩余缺口并给出最短补齐路线。
- 与用户有关的重大新需求或需要破坏现有成果的改动，先请示；本独立实验工程内部的常规技术选型和修复已授权自主进行。
